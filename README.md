# 投资 X Buddy

面向投资研究者的个人 **Agent 工作台**：用户给出一个研究目标，系统规划任务、调用金融工具取证、管理上下文与长期状态，产出**可验证、可追溯**的研究成果，并在需要时请求确认。

> 本项目为秋招笔试题「题目 13｜投资 X Buddy」的提交。运行环境：Node.js ≥ 20、Next.js 16。

---

## 一、用户与要解决的问题

- **用户**：需要快速验证投资命题的研究者（覆盖基本面、估值、公告、研报等维度），希望每一个结论都能回到原始字段，而不是一句「我感觉」。
- **痛点**：研究目标通常是模糊的（如「盈利改善来自主营业务」）。人很难同时做到「拆成可验证子问题 → 调数据 → 分正反证据 → 下可追溯结论 → 说明什么会推翻它」。
- **本产品**：把这条链交给一个 Agent 主链路自动完成，同时把 Agent 的每一步（计划、工具、成本、时延）都暴露给用户看。

## 二、主链路（核心体验）

`app/api/agent/route.js` 把**七层 Harness** 串成一条可审计的流水线（分层详解见 [docs/HARNESS.md](docs/HARNESS.md)）。

```
输入研究目标
  → ① 上下文管理：建立线程
  → ④ 安全与治理：输入校验（不通过则 400 拦截）
  → ③ 任务编排：规划器拆任务（LLM 或离线模板）
  → ④ 安全与治理：逐工具审批 + 审计留痕（写操作/未注册 → 拒绝）
  → ③+⑦ 编排 + 恢复：执行器调度工具（重试/熔断/停止规则）
  → ③ 任务编排：综合器生成 支持/反对/无法验证 证据链 + 结论
  → ⑤ 校验反馈：自检报告（覆盖/冲突/完整性/打分）
  → ④ 安全与治理：合规扫描 + 敏感信息防护
  → ① 上下文管理：证据写入工作记忆，超阈值自动压缩
  → ⑥ 可观测性：成本/时延/步数汇总
  → ⑦ 异常恢复：落盘检查点（可恢复）
  → 返回 run（结论 + 七层运行报告 + 可追溯来源）
```

界面把这条链映射成：**线程/任务计划**、**证据（支持/反对/无法验证，每条可追溯来源）**、**结论（含置信度与翻转条件）**、**可观测（步骤/成本/时延）+ 七层 Harness 运行报告**。支持多标的**比较**、**恢复历史运行**（检查点）。

## 三、产品设计选择

1. **数据源与工具解耦（适配器层）**：工具只声明「要什么」，数据从哪来由 `adapters.js` 决定。默认 `mock` 示例数据即可离线跑通全链路；`fuyao` 已接入扶摇真实端点，`iFinD` 待 MCP client。接真数据只改适配器、不动 Agent。
2. **确定性的证据分类 + LLM 负责拆解**：证据的「支持/反对/无法验证」用可审计的阈值规则判定（如主营占比 ≥95% 记为支持），保证每个结论都能回到字段与阈值；LLM（DeepSeek）负责「把目标拆成子问题」这类需要理解的任务。**LLM 挂了会降级到离线规则，主链路不断。**
3. **结论永远是「推断/不确定」，不是关于未来的「事实」**：单条证据标「事实/推断/外部参考」，整体结论只标「推断/不确定」——从产品结构上杜绝把观点包装成事实。
4. **失败即「无法验证」，不假装正常**：数据缺失、接口失败、工具未注册，统一降级为「无法验证 + 原因」，绝不静默生成正常结论。

## 四、AI 的角色

| 环节 | 是否用 LLM | 说明 |
| --- | --- | --- |
| 任务规划（拆目标） | ✅ DeepSeek | 无 key 时降级为离线关键词模板 |
| 证据分类（支持/反对） | ❌ 确定性规则 | 可审计、可测试 |
| 结论措辞 | ❌ 确定性模板 | 基于证据计数与阈值 |
| 翻转条件 | ❌ 确定性规则 | 由支持证据所依赖的阈值反推 |

AI 使用与验证记录见 [docs/AI_USAGE.md](docs/AI_USAGE.md)。

## 五、数据来源

- **当前（默认）**：`mock` —— 内置的**示例数据**（宁德时代 300750、贵州茅台 600519、隆基绿能 601012、沪深300），全部为构造值，仅供演示，**不是真实行情/财报**。界面顶部会明确显示「数据源：mock」。
- **扶摇（真实数据）**：已接入官方 HTTP 端点（`https://fuyao.aicubes.cn`，认证头 `X-api-key`），覆盖行情快照、估值（PE/PB/PS/PCF）、年度财报（利润表 + 现金流量表，据此计算毛利率、营收/归母净利同比、经营现金流）、历史 K 线、指数。配置 `FUYAO_API_KEY` 并把 `DATA_SOURCE=fuyao` 即可。**扶摇不提供 A 股公告/研报接口，这两类工具会诚实返回「无法验证」**；历史估值分位、主营收入占比、非经常性损益占比也无，界面会如实标注为「无数据」，不硬凑。
- **iFinD MCP**：MCP 协议（https://mcp.51ifind.com/），需要 MCP client 接入，当前**未接入**（见未做事项）。

## 八、测试说明

运行 `npm test`（Node 内置测试，无需任何 key，纯离线确定性），共 **21 个用例**：覆盖题目要求的三类必需场景（主链路 / 数据缺失·接口失败 / 极端·合规边界）、七层 Harness 的关键行为，以及**扶摇真实数据适配器**的端点解析与归一化（mock 掉 fetch，不联网）。完整用例清单与手工验证步骤见 [docs/TESTING.md](docs/TESTING.md)。

## 九、合规

- 不输出确定性涨跌预测、收益承诺、买卖建议（`lib/compliance.js` 对结论文本做违禁扫描）。
- 事实 / 推断 / 不确定 / 外部参考四类标签在证据与结论上显式区分。
- 每条证据可「追溯来源」：工具、数据源、标的、字段、值、单位、期间、时点。
- 数据缺失/冲突/失败一律显式标注，不静默。

## 十、已知边界与未做事项

- **数据**：默认 mock 示例数据；扶摇已接入真实行情/估值/财报/K线/指数，但无 A 股公告、研报、历史估值分位、主营占比、非经常损益（界面如实标注为「无数据」）；iFinD 需 MCP client，尚未接入。
- **持久化**：检查点保存在内存 + 本地文件；部署到 Vercel 等 serverless 环境后文件系统只读，**跨请求/跨实例的持久化需要接数据库**（未做）。
- **上下文跨进程**：线程/工作记忆/长期记忆为单实例内存实现（`lib/agent/context.js`），未做跨请求持久化；部署到 Vercel 后需接数据库才能跨实例共享。
- **审批 UI**：写操作类工具的「人工审批」策略已实现（`lib/agent/governance.js`），但当前 7 个工具均为只读，前端未暴露审批交互。
- **结论措辞的 LLM 增强**：结论目前用确定性模板，可用 LLM 进一步润色（规划环节已用 LLM）。
- **token 计量**：离线模式下 token 为字符数估算（界面已标注），接 DeepSeek 后可读 `usage` 精确计费。
