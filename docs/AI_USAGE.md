# AI 使用与验证记录

## 一、使用了哪些 AI 工具

| 工具 | 用途 | 参与环节 |
| --- | --- | --- |
| Claude Code（Anthropic） | 架构设计、代码生成、测试编写、文档撰写 | 贯穿全流程 |
| DeepSeek（deepseek-chat） | 产品运行时的大模型：把研究目标拆解为可验证子问题 | 规划器（可插拔，无 key 时降级为离线规则） |
| Radix UI / Lucide / Recharts | 开源 UI 组件 / 图标 / 图表库（**非生成式 AI**） | 前端交互与可视化 |

## 二、AI 参与哪些环节

1. **七层 Harness 架构设计**：上下文管理、工具调度、任务编排、安全与治理、校验反馈、可观测性、异常恢复的模块拆分与职责划分。
2. **主链路实现**：规划（planner）→ 执行（executor）→ 综合（synthesizer）→ 合规（compliance）→ 检查点/记忆（state）。
3. **治理层**：输入校验、工具审批策略（read 自动批准 / write 转人工 / 未注册拒绝）、审计日志、敏感信息防护、合规违禁扫描。
4. **校验反馈层**：目标覆盖 / 冲突 / 完整性 / 置信度自检与打分。
5. **异常恢复层**：瞬时重试、熔断器、降级链路。
6. **前端 UI**（Next.js App Router + Radix/Lucide/Recharts）与「七层 Harness 运行报告」面板。
7. **测试与文档**：12 个测试用例、README、TESTING.md、HARNESS.md、本文档。

## 三、候选人修正的错误与不合理结果

1. **核心功能命名曾被品牌化**：早期把「开始研究 / 运行日志 / 历史检查点」等核心功能改成了诗化的品牌词，违背「核心功能与按钮必须是专业金融术语」的原则。候选人指出后，恢复为专业金融术语；品牌（观隅 / 名称 / slogan / 配色 / logo）仅作用于 UI 视觉层。
2. **交互与视觉初版偏弱**：初版仅自绘基础样式。候选人反馈「交互和界面设计差」后，改用开源组件库（Radix Collapsible / ScrollArea、Lucide 图标、Recharts 图表）重做交互与可视化。
3. **数据处理流程**：候选人要求「先给代码、不要后台自行计算」，改为把数据处理以代码形式交付、由候选人审阅后再运行。
4. **合规红线从口号落到程序**：违禁表述扫描、免责声明、事实/推断/不确定三色区分、证据可追溯来源、数据缺失显式「无法验证」。
5. **数据诚实性**：mock 示例数据全程明确标注「示例/构造数据」，不冒充真实行情；接真数据只加适配器、不改结论生成逻辑。

> 建议候选人补充：自己做过的产品决策、部署与演示视频、以及个人认为需要记录的人工修正。

## 四、AI 生成内容的验证情况

- **代码正确性**：12 个测试用例全绿（`npm test`）；`npm run build` 通过。
- **合规正确性**：测试断言结论不含确定性涨跌预测 / 买卖建议 / 收益承诺，并附免责声明。
- **尚未验证（需真实 key / 账号）**：扶摇真实端点的**在线**连通性（端点解析与归一化已有 9 个离线单测覆盖，真实调用需 `FUYAO_API_KEY`）；iFinD（需 MCP client，未接入）；DeepSeek 真实计费（离线模式下为字符数估算，已标注）。
