# AI 使用与验证记录

> 说明：本文件按题目要求记录「使用了哪些 AI 工具、AI 参与哪些环节、候选人修正了哪些错误或不合理结果」。请候选人在提交前核对并补充「候选人修正」部分，使其真实反映自己的过程。

## 一、使用的 AI 工具

| 工具 | 用途 |
| --- | --- |
| Claude Code（AI 编程代理） | 产品架构设计、代码实现、测试编写、README 起草 |
| DeepSeek（`deepseek-chat`，产品内 LLM） | 主链路「任务规划」环节，把研究目标拆成可验证子问题并选工具 |

## 二、AI 参与哪些环节

1. **技术栈选型**：AI 建议 Next.js 全栈 + Vercel 部署（单仓库装前后端、一次部署拿公开 URL），候选人确认。
2. **产品架构**：AI 设计「工具注册表 → 数据适配层 → Agent（规划/执行/综合）→ 状态/合规/可观测」分层。
3. **Agent 主链路**：AI 实现 规划 → 执行 → 综合 → 检查点 → 合规 的完整闭环。
4. **合规逻辑**：AI 把题目红线（不预测涨跌、区分事实/推断、可追溯、失败不静默）落成 `compliance.js` 与确定性证据规则。
5. **测试**：AI 编写覆盖主链路/数据缺失/合规边界/停止规则的四组测试。

## 三、候选人修正的错误或不合理结果

> 请填写你在过程中发现并让 AI 修正的点。示例格式（可替换为你的真实情况）：

1. （示例）发现「非经常性损益占比」的阈值设置不合理，要求把支持/反对的分界从 10% 调整为 5%/15%。
2. （示例）发现研究报告中「买入/增持」评级直接透传会触碰「买卖建议」红线，要求统一标注为「外部观点，仅供参考」。

## 四、如何验证 AI 产出

- 后端逻辑：`npm test`（4 组离线确定性测试全部通过）。
- 端到端：`npm run dev` 后访问 http://localhost:3000，输入示例目标验证主链路与 UI。
- 数据真实性：产品内明确标注 mock 示例数据，接真实数据前不宣称真实行情/财报。
