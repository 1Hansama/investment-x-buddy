# 观隅（投资 X Buddy）· 七层 Harness 功能介绍

> 一个把「研究目标 → 可追溯结论」全链路工程化的个人投研 Agent 工作台。
> 技术栈：Next.js 16（App Router）+ React 19 + DeepSeek（可插拔）+ 数据适配层（mock / 扶摇 / iFinD）。
> 全部逻辑离线可跑、可单测；数据源、模型均可替换，不绑死任何一家。

我们把一个金融 Agent 拆成 **七层 Harness**，每层是一个可独立测试、可替换的模块。它们共同回答题目里最重要的几条要求：**能力/工具注册、计划执行、上下文压缩、记忆、检查点与恢复、权限/审批、停止规则、成本时延、可观测性、降级与恢复**。

---

## 七层总览

| # | Harness | 职责一句话 | 覆盖的题目要求 | 落地文件 |
|---|---------|-----------|---------------|---------|
| 1 | 上下文管理 | 线程 + 工作/长期记忆 + 上下文压缩 | 上下文压缩、记忆、长期状态 | `lib/agent/context.js` |
| 2 | 工具调度层 | 能力注册表 + 数据适配 + 风险分级 | 能力/工具注册、可插拔 | `lib/tools.js`、`lib/adapters.js` |
| 3 | 任务编排 | 规划 → 执行 → 综合的编排收口 | 计划执行 | `lib/agent/planner.js`、`executor.js`、`app/api/agent/route.js` |
| 4 | 安全与治理 | 输入校验、审批、审计、合规、敏感防护 | 权限/审批、停止规则、合规 | `lib/agent/governance.js`、`lib/compliance.js` |
| 5 | 校验反馈 | 目标覆盖/冲突/完整性自检 | 事实·推断·不确定区分 | `lib/agent/validation.js`、`synthesizer.js` |
| 6 | 可观测性 | 每一步留痕 + 成本/时延/状态统计 | 成本时延、可观测性 | `lib/agent/observability.js` |
| 7 | 异常恢复 | 重试、熔断、降级、检查点恢复 | 降级与恢复、检查点与恢复 | `lib/agent/recovery.js`、`state.js` |

## 逐层详解

### 1. 上下文管理 —— 让 Agent 有「工作记忆」和「长期记忆」

**做了什么**
- **线程（thread）**：每次研究目标建立一个线程，同一线程内的多轮追问共享上下文。
- **工作记忆（working memory）**：本次研究的证据条目，超过阈值（12 条）自动触发压缩。
- **长期记忆（long term）**：被压缩下来的摘要，跨轮可复用。
- **上下文压缩**：`compressEntries` 把「支持 N / 反对 M + 关键要点」压成一段紧凑摘要，而不是无脑截断。

**为什么这样设计**
长对话/长研究的真正痛点不是「存不下」，而是「关键结论被无关细节淹没」。所以我们用「先压缩、后丢弃」的策略：只保留结构化摘要（支持/反对计数 + 要点），把原始条目降级到长期记忆，保证后续轮次仍能引用核心结论。

**对标主流**：多数聊天式金融助手（问财、Wind Alice 的对话模式）是「一次性问答」，不保留跨轮可复用记忆；开源框架（LangChain memory）提供的是通用 KV 记忆，不关心金融语义。我们把压缩口径做成「金融证据维度」的——按支持/反对归纳，而不是按 token 长度截断。

---

### 2. 工具调度层 —— 能力集中注册，数据源可插拔

**做了什么**
- **能力注册表**：7 个金融工具（行情快照、估值、财务、K 线、公告、研报、指数）集中登记，每个声明名称/描述/入参/分类/**风险等级（riskLevel）**。
- **数据适配层**：`mock | fuyao | ifind` 三套适配器，改环境变量即可切换；未来接真数据**只加适配器、不改任何 Agent 代码**。
- **诚实降级契约**：数据源不可用时不抛异常，返回 `{ok:false, reason}`，让上层明确降级成「无法验证」——绝不用假数据冒充正常结论。

**为什么这样设计**
「能力注册」的价值在于：规划器只依据注册表选工具，治理层只依据 `riskLevel` 审批，执行器只按名字调度。三者解耦后，新增一个工具或换一个数据源，都是一处改动。

**对标主流**：iFinD / 万得是「数据 + 终端」，能力强但闭源、付费、难接入个人演示；OpenBB、LangChain Tool 是通用工具抽象，没有「金融工具必须带来源/口径/单位」的约束。我们给每个工具返回值强制带上 `source`（来源、标的、时点、字段、单位），这是后面「结论可追溯」的地基。

---

### 3. 任务编排 —— 从目标到结论的编排收口

**做了什么**
- **规划器**：把研究目标拆成「能用数据工具验证」的子问题（3–6 个），有 DeepSeek 用 LLM 拆解，没 key 用离线关键词模板兜底，**模型挂了主链路也不断**。
- **执行器**：按计划逐个调用工具、收集证据，每一步都过停止规则（步数上限 12 / 时延上限 30s）。
- **编排收口**：`route.js` 把规划→审批→执行→综合→校验→合规→检查点串成一条可审计的流水线，并输出编排统计（规划 N / 执行 M / 无法验证 P / 停止 Q）。

**为什么这样设计**
把「编排」和「执行」分开：编排决定**顺序与门槛**（审批、预算、停止），执行只负责「调用工具并诚实记录结果」。这样未来加并行、加依赖、加多轮，都只改编排层。

**对标主流**：LangGraph / CrewAI 提供图式/多智能体编排，但把「金融合规约束」丢给开发者自己写；我们的编排把「停止规则」「审批门槛」「降级路径」内置为默认行为，开箱即符合题目红线。

---

### 4. 安全与治理 —— 权限、审批、审计、合规、敏感防护

**做了什么**（这是最容易「看起来有、实际没有」的一层，我们全部做成可运行的函数）
- **输入校验**：拒绝空目标、超长目标、疑似越权/注入式指令（如「忽略所有指令」）。
- **工具审批**：按 `riskLevel` 走策略——`read` 只读工具自动批准，`write` 写操作转人工审批，未注册工具直接拒绝。当前所有工具只读，因此**审批链路是真实存在且可升级的**，不是写死在注释里。
- **审计日志**：每次审批决策都留痕（时间、工具、标的、结论），随结果返回前端，可追溯。
- **合规扫描**：产品自身输出绝不含「目标价 / 建议买入卖出 / 确定性涨跌 / 收益承诺」；事实、推断、不确定信息三色区分；每条结论附免责声明。
- **敏感信息防护**：扫描产物是否疑似泄露 API Key / PAT / 身份证 / 手机号。

**为什么这样设计**
金融产品的信任来自「可解释 + 可审计」。审批不是摆设：策略表 + 风险等级是数据，不是 if-else 硬编码；审计日志让「谁在什么时候批准了什么」可查。

**对标主流**：机构级产品（Bloomberg、券商研报 AI）有完善合规但黑盒；开源框架几乎不内置金融合规。我们把「合规红线 + 审批 + 审计」做成独立的治理层，且**离线可单测**（见 `tests`），这是个人项目里少见的完整度。

---

### 5. 校验反馈 —— 产出前先自检一遍

**做了什么**
- **完整性**：每个标的要么有证据、要么有明确的「无法验证」说明，不允许静默空白。
- **目标覆盖**：无法验证项多于可验证证据时，明确提示「结论可信度受限」。
- **冲突检测**：同一字段（如毛利率）同时出现支持与反对，标记需复核口径。
- **置信度兜底**：置信度过低的结论提示补数据。
- **打分**：综合缺口/冲突/低置信度给校验分（0–1），并给出一句结论性说明。

**为什么这样设计**
题目要求「数据缺失、冲突、过期时不得静默生成正常结论」。校验反馈层是这条红线的**程序化兜底**：综合器（synthesizer）负责「生成」，校验器（validation）负责「质疑」，两者分离，避免自己给自己打满分。

**对标主流**：大多数金融 Agent 只输出结论、不输出「这条结论有多少把握、哪里可能有坑」。我们把「翻转条件 + 冲突说明 + 校验分」一起给用户，把「置信」从形容词变成可量化的信号。

---

### 6. 可观测性 —— 每一步都在账上

**做了什么**
- 每一步（规划、工具调用、停止）都写入 trace，带步骤号、类型、耗时、状态（done / unverifiable / stopped）。
- **成本与口径**：token 估算 → 金额（按 DeepSeek 示例价，可配置），时延按毫秒累计，状态计数汇总。
- 前端「运行日志」侧边栏实时展示每一步 + 步骤/工具/时延/token/成本统计。

**为什么这样设计**
「Agent 到底干了什么、花了多少钱」如果不可见，就无法治理。我们把可观测性做成**随结果一起返回的结构化数据**，前端只是渲染它——这也让审计和复盘有了同一份事实来源。

**对标主流**：商用平台的可观测性往往锁在后台；开源框架的 tracing 偏开发者视角。我们把成本/时延/步数直接摊给最终用户看，契合题目「成本时延」的考察点。

---

### 7. 异常恢复 —— 失败不等于中断

**做了什么**
- **降级链路**：模型失败 → 离线规则；工具失败/数据缺失 → 无法验证；检查点写盘失败 → 内存兜底。任何单点失败都不中断主链路。
- **瞬时重试**：工具抛异常（网络抖动/超时）自动重试一次；确定性缺失（`{ok:false}`）不重试，避免空耗。
- **熔断**：同一工具连续异常达到阈值即熔断，冷却期后再试——防止「坏数据源」拖垮整个运行。
- **检查点与恢复**：每次运行落盘为检查点，可 `load` 恢复（`state.js`）。

**为什么这样设计**
真实世界里数据源一定会挂。区分「瞬时故障（值得重试）」和「确定性缺失（不该重试）」、再用熔断止损，是把「降级」从口号变成工程动作。

**对标主流**：通用 Agent 框架有 retry 但少有面向「数据源健康」的熔断；金融数据平台挂了通常直接报错。我们把「重试 + 熔断 + 降级 + 检查点」四件套合在一起，保证演示和真实环境都能体面失败。

## 一次完整运行：七层如何协同

```
用户目标
  → ① 上下文管理：建立线程
  → ④ 安全与治理：输入校验（不通过则 400 拦截）
  → ③ 任务编排：规划器拆任务（LLM 或离线模板）
  → ④ 安全与治理：逐工具审批 + 审计留痕（写操作/未注册 → 拒绝）
  → ③+⑦ 任务编排 + 异常恢复：执行器调度工具（重试/熔断/停止规则）
  → ③ 任务编排：综合器生成「支持/反对/无法验证」证据链 + 结论
  → ⑤ 校验反馈：自检报告（覆盖/冲突/完整性/打分）
  → ④ 安全与治理：合规扫描 + 敏感信息防护
  → ① 上下文管理：证据写入工作记忆，超阈值自动压缩
  → ⑥ 可观测性：成本/时延/步数汇总
  → ⑦ 异常恢复：落盘检查点（可恢复）
  → 返回 run（结论 + 七层报告 + 可追溯来源）
```

## 与主流金融 Agent 的横向对比

| 维度 | 观隅（本项目） | 问财 / iFinD 智能问答 | Wind Alice / 券商 AI | 开源框架（LangGraph/CrewAI/FinGPT/OpenBB） |
|---|---|---|---|---|
| 结论可追溯 | ✅ 每条证据回到原始字段+来源+时点+单位 | ⚠️ 数据罗列，少给推理链 | ⚠️ 结论专业但过程黑盒 | ❌ 需自行实现 |
| 事实/推断/不确定区分 | ✅ 三色印章系统 | ❌ | ⚠️ 部分 | ❌ 需自行实现 |
| 权限/审批/审计 | ✅ 风险分级 + 策略审批 + 审计日志 | ⚠️ 平台侧管控 | ✅ 机构合规 | ❌ 需自行实现 |
| 降级与恢复 | ✅ 重试/熔断/降级/检查点 | ⚠️ 直接报错 | ⚠️ | ⚠️ 通用 retry |
| 成本/时延可观测 | ✅ 结构化成本+时延+步数 | ❌ | ⚠️ | ⚠️ 偏开发者 |
| 数据源可插拔 | ✅ mock→扶摇→iFinD 一处切换 | 绑定自身数据 | 绑定自身数据 | ✅ 通用 |
| 离线可跑可测 | ✅ 无 key 也能跑通+单测 | ❌ 依赖服务 | ❌ 依赖服务 | ✅ 但金融语义要自己补 |
| 合规红线内置 | ✅ 违禁词+免责+敏感防护 | ⚠️ | ✅ | ❌ |

**一句话定位**：主流金融 Agent 强在「数据全、模型大」，但往往黑盒、绑定平台、缺少可审计的推理链；本项目的护城河是**把金融合规约束工程化为七层可测试的 Harness**——结论可追溯、过程可审计、失败可恢复、离线可演示。

## 诚实边界（未做事项）

- 检查点持久化：Vercel 文件系统只读，线上持久化到数据库尚未做（本地 `data/state/*.json` 可恢复）。
- 真实数据接入：扶摇/iFinD 留了接口骨架，需配 key / MCP client；当前演示用构造的 mock 数据。
- 上下文跨进程：线程/记忆为单实例内存实现，未做跨请求持久化。
- token 计数：离线模式下为字符数估算（标注为估算），接 DeepSeek 后可读 `usage` 精确计费。
- 审批 UI：写操作类工具的「人工审批」策略已实现，但当前无写操作工具，前端未暴露审批交互。
